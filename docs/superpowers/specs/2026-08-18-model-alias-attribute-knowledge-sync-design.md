# 通用型号、产品属性与知识库自动更新设计

日期：2026-08-18  
状态：用户已确认方案

## 目标

1. 客户询价中使用 `/`、`or`、`and` 连接的型号视为通用型号，任意一个命中即可匹配内部型号。
2. 报价结果展示价格体系“属性”列中的自制/调货信息。
3. 用户在型号匹配、报价、二次校对中确认的关系统一写入型号知识库，形成可追溯版本并支持下载。
4. 最新型号库导出中，用户新增的具体内容使用黄色字体，与原始数据区分。

## 通用型号解析

- 连接符包括 `/`、大小写不敏感的 `or`、大小写不敏感的 `and`。
- 连接符仅在两个型号之间起分隔作用，括号和首尾空格在匹配前清理。
- 原始整串文本保留在报价“客户输入”列中，用于追溯。
- 拆出的型号逐个进行本地知识库匹配并合并去重结果。
- 任意一个型号唯一命中时，该询价行使用对应内部型号完成报价。
- 多个型号命中同一内部型号时直接确认，不重复生成候选。
- 多个型号命中不同内部型号时，先执行现有规则：A1 优先于 A、B1 优先于 B、8 位及以内优先；仍无法唯一确定时展示内部型号下拉选择。
- 用户确认后，所有拆出的有效通用型号都与最终内部型号建立关系。

## 自制/调货属性

- 价格库解析时识别价格表的“属性”列。
- 价格数据库记录新增 `attribute` 字段；同一内部型号的价格档位共享该型号的属性信息。
- 报价页面在“内部型号”与价格列之间增加“属性”列，展示自制、调货或源表中的其他原值。
- 报价 Excel 下载增加“属性”列。
- 价格库下载保留“属性”列。
- 属性缺失时显示空值，不进行猜测。

## 知识库自动更新

- 型号匹配手动确认、报价候选选择、报价手动填写、二次校对确认统一调用同一个确认服务。
- 确认服务负责：创建或定位内部型号、拆分通用型号、判断 OE/UF/老型号、更新型号表、刷新查询索引、写入校对记录、生成型号库版本。
- UF 开头的编号只进入 UF 字段，其他外部编号默认进入 OE 字段，DQ 开头且不等于内部型号的编号进入老型号字段。
- 已存在的关系不重复写入，也不重复生成版本。
- 每次产生实际新增关系时生成新的型号库版本 `M002`、`M003` 等，版本记录包含操作人、时间、来源入口、新增关系数和当前总型号数。
- 知识库页面刷新后展示最新版本；下载按钮名称为“下载最新大厂型号匹配表”。

## 黄色新增标记

- 型号库导出使用可写样式的 Excel 生成方式。
- 原始数据保持黑色字体。
- 用户确认新增的内部型号、老型号、OE、UF仅对新增文本设置黄色字体；同一单元格中的原始内容保持黑色。
- 新增内容的判定来自已确认记录，不依赖当前页面缓存。
- 导出字段维持：货品编码、对外型号、老型号、OE号、UF号、适用车型、货品类别、数据来源、外网确认OE、外网确认UF。

## 数据一致性与异常处理

- 确认关系、索引刷新、校对记录和版本记录必须在同一事务内完成，任一步失败则整体回滚。
- 多人同时确认时由现有持久化锁串行写入，避免覆盖。
- 旧历史确认记录在导出时也用于识别用户新增内容；原始匹配表中本来存在的数据不着黄色。
- 外网候选未经用户勾选确认不得进入型号库。

## 验收标准

1. `10353257 (or 10239858)` 中任一编号命中时可得到相同内部型号与价格。
2. `22448-4M500 and 22448-6N015` 可拆分并按任一编号命中；若两者指向不同型号则进入候选选择。
3. `/` 连接的三种型号可逐个查询，原始文本仍完整显示。
4. 报价页面及下载文件均显示对应“属性”。
5. 三个确认入口产生的新增关系均能立即被型号查询命中。
6. 知识库版本从 M001 正确递增，显示当前时间与操作人。
7. 下载的最新大厂型号匹配表包含新增关系，且只有新增文本为黄色字体。
